OpenCode은 네트워크 액세스 제한 및 시스템 활동 모니터링을 위한 포괄적인 보안 제어 기능을 제공합니다. 이러한 기능은 AI 어시스턴트가 통신할 수 있는 외부 서비스를 제어해야 하는 내부 전용 환경에 맞게 설계되었습니다.

---

## 보안 모드

OpenCode은 네트워크 요청을 유효성 검사하는 방법을 결정하는 세 가지 보안 모드를 지원합니다:

### `internal-only` (내부 환경의 기본값)

`internal-only`는 Localhost, 사내 IP 및 구성된 내부 도메인만 허용합니다. 명시적으로 허용되지 않는 한 모든 외부 URL은 차단됩니다.

```json title="opencode.json"
{
  "security": {
    "mode": "internal-only"
  }
}
```

### `external-allowed`

`external-allowed`는 모든 URL을 허용하지만 감사 목적을 위해 외부 URL을 기록합니다. 이 모드는 차단 없이 네트워크 활동을 모니터링하는 데 유용합니다.

```json title="opencode.json"
{
  "security": {
    "mode": "external-allowed"
  }
}
```

### `strict`

`strict`는 명시적으로 `external_domains`에 구성된 도메인, localhost, 사내 IP 및 내부 DNS 접미사와 일치하는 URL만 허용됩니다. 다른 모든 URL은 차단됩니다.

```json title="opencode.json"
{
  "security": {
    "mode": "strict"
  }
}
```

## 구성 옵션

모든 보안 구성은 OpenCode 설정 파일의 `security` 키 아래에 배치됩니다.

### `mode`

보안 모드 선택. 다음 중 하나: `"internal-only"`, `"external-allowed"`, `"strict"`.

```json title="opencode.json"
{
  "security": {
    "mode": "strict"
  }
}
```

### `allow_internal_dns_suffixes`

허용할 내부 DNS 접미사 배열. 하위 도메인 일치를 위해 와일드카드를 포함할 수 있습니다.

```json title="opencode.json"
{
  "security": {
    "allow_internal_dns_suffixes": [".internal.corp.com", ".dev.internal"]
  }
}
```

이 구성으로 `api.internal.corp.com` 및 `db.dev.internal`이 허용됩니다.

### `block_domain_regex`

일치시켜 차단할 특정 도메인 또는 패턴의 정규식 배열.

```json title="opencode.json"
{
  "security": {
    "block_domain_regex": [".*\\.evil\\.com$", ".*\\.test\\.com$"]
  }
}
```

### `allow_local`

Localhost URL 허용 (기본값: `true`).

```json title="opencode.json"
{
  "security": {
    "allow_local": true
  }
}
```

### `allow_private_ip`

사내 IP 주소 허용 (기본값: `true`).

포함되는 사내 IP 범위:

- `10.0.0.0/8` (Class A)
- `172.16.0.0/12` (Class B)
- `192.168.0.0/16` (Class C)
- `127.0.0.0/8` (Loopback)
- `::1` (IPv6 루프백)

```json title="opencode.json"
{
  "security": {
    "allow_private_ip": true
  }
}
```

### `models_dev_enabled`

`models.dev`에서 모델 목록을 가져오기 활성화 (기본값: `true`). 비활성화 시 OpenCode은 models.dev에서 최신 모델 목록을 가져오지 않습니다.

```json title="opencode.json"
{
  "security": {
    "models_dev_enabled": false
  }
}
```

### `audit_log_enabled`

감사 로그 활성화 (기본값: `true`). 활성화 시 보안 이벤트가 `~/.config/opencode/audit.jsonl`에 기록됩니다.

```json title="opencode.json"
{
  "security": {
    "audit_log_enabled": true
  }
}
```

### `external_domains`

`strict` 모드에서 명시적으로 허용되는 외부 도메인. 와일드카드 패턴을 지원합니다.

```json title="opencode.json"
{
  "security": {
    "mode": "strict",
    "external_domains": ["api.openai.com", "*.azure.com", "api.anthropic.com"]
  }
}
```

`*.azure.com` 패턴으로 `my-resource.openai.azure.com`과 같은 URL이 허용됩니다.

### `allow_external_ips`

외부/공용 IP 주소 허용 (기본값: `false`). `mode`가 `"internal-only"`인 경우에만 적용됩니다.

```json title="opencode.json"
{
  "security": {
    "mode": "internal-only",
    "allow_external_ips": false
  }
}
```

### `allowed_ip_ranges`

CIDR 표기법의 추가 허용 IP 범위.

```json title="opencode.json"
{
  "security": {
    "allowed_ip_ranges": ["192.168.100.0/24", "10.0.0.0/8"]
  }
}
```

## 프로바이더 보안

보안 제어는 다음을 포함한 모든 프로바이더 구성에 적용됩니다:

- OpenAI
- Azure OpenAI
- Anthropic
- Amazon Bedrock
- Google Gemini
- 로컬 모델 (llama.cpp, Ollama)
- 사용자 정의 프로바이더

프로바이더에 사용자 정의 `baseURL` 또는 엔드포인트가 구성되면, 프로바이더가 로드되기 전에 URL이 보안 구성에 따라 유효성 검사됩니다.

### 예시: 사용자 정의 엔드포인트를 가진 OpenAI

```json title="opencode.json"
{
  "security": {
    "mode": "strict",
    "external_domains": ["api.openai.com"]
  },
  "provider": {
    "openai": {
      "options": {
        "baseURL": "https://api.openai.com/v1"
      }
    }
  }
}
```

`baseURL`이 허용된 도메인과 일치하지 않으면 프로바이더가 차단되고 오류가 기록됩니다.

## 감사 로그

감사 로그는 `~/.config/opencode/audit.jsonl`에 모든 보안 관련 이벤트를 기록합니다.

### 로그 항목 구조

각 항목은 다음을 포함합니다:

- `timestamp`: ISO 8601 타임스탬프
- `type`: 이벤트 카테고리 (`url_check`, `provider_load`, `tool_request`, `blocked_access` 등)
- `level`: `info` 또는 `warn`
- `message`: 사람이 읽을 수 있는 설명
- `context`: 추가 컨텍스트 (URL, 프로바이더 ID, 도구 이름)
- `metadata`: 기계가 읽을 수 있는 데이터 (허용 상태, 모델 수 등)

### 이벤트 유형

| 유형                   | 설명                    |
| ---------------------- | ----------------------- |
| `url_check`            | URL 유효성 검사 성공    |
| `blocked_access`       | URL 유효성 검사 실패    |
| `provider_load`        | 프로바이더 로드 시도    |
| `model_access`         | 모델 액세스 시도        |
| `tool_request`         | 도구 네트워크 요청 허용 |
| `tool_blocked`         | 도구 네트워크 요청 차단 |
| `fetch_request`        | HTTP 요청 실행          |
| `session_model_change` | 세션 모델 변경 시도     |

### 예시 감사 로그

```json
{"timestamp":"2024-01-15T10:30:00.000Z","type":"blocked_access","level":"warn","message":"URL not in allowlist (mode: strict)","context":{"url":"https://api.evil.com","providerId":"openai"},"metadata":{"allowed":false}}
{"timestamp":"2024-01-15T10:30:05.000Z","type":"provider_load","level":"info","message":"Provider loaded: openai (custom, 150 models)","context":{"providerId":"openai","source":"config"},"metadata":{"modelsCount":150,"allowed":true}}
```

### 감사 로그 보기

감사 로그는 append-only입니다. 다음과 같이 최근 항목을 볼 수 있습니다:

```bash
tail ~/.config/opencode/audit.jsonl
```

## 예시 구성

### 내부 액세스를 위한 Strict 보안

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "security": {
    "mode": "strict",
    "allow_local": true,
    "allow_private_ip": true,
    "models_dev_enabled": true,
    "audit_log_enabled": true,
    "allow_internal_dns_suffixes": [".internal.corp.com", ".dev.internal"],
    "external_domains": ["api.openai.com", "*.azure.com", "api.anthropic.com"],
    "allowed_ip_ranges": ["192.168.100.0/24", "10.0.0.0/8"]
  },
  "provider": {
    "openai": {
      "options": {
        "apiKey": "{env:OPENAI_API_KEY}"
      }
    },
    "anthropic": {
      "options": {
        "apiKey": "{env:ANTHROPIC_API_KEY}"
      }
    }
  }
}
```

### 외부 액세스 로깅을 위한 개발 환경

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "security": {
    "mode": "external-allowed",
    "allow_local": true,
    "allow_private_ip": true,
    "audit_log_enabled": true
  }
}
```

### 사용자 정의 블랙리스트를 가진 Internal-Only

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "security": {
    "mode": "internal-only",
    "allow_local": true,
    "allow_private_ip": true,
    "block_domain_regex": [".*\\.sandbox.*", ".*\\.test.*"],
    "allow_internal_dns_suffixes": [".corp.local"]
  }
```

## Models.dev 제어

`models_dev_enabled` 옵션은 OpenCode이 `https://models.dev`에서 최신 모델 목록을 가져올 수 있는지 제어합니다.

### 작동 방식

1. 시작 시 OpenCode은 `models_dev_enabled`가 `false`인지 확인합니다
2. 비활성화된 경우 최신 모델을 가져오지 않고 캐시/알려진 모델만 사용합니다
3. 활성화된 경우 보안 유효성 검사를 거쳐 models.dev에서 모델을 가져옵니다

### models.dev 비활성화

```json title="opencode.json"
{
  "security": {
    "models_dev_enabled": false
  }
}
```

비활성화 시:

- `"models.dev fetching is disabled by security configuration"` 메시지가 로그에 표시됩니다
- OpenCode에 이미 알려진 모델만 사용할 수 있습니다
- 오프라인 환경이거나 사용 가능한 모델을 엄격하게 제어하려는 경우에 유용합니다

## 도구 실행

### webfetch 도구

`webfetch` 도구는 콘텐츠를 가져오기 전에 보안 구성에 따라 URL을 유효성 검사합니다:

1. URL 형식 확인 (`http://` 또는 `https://`로 시작해야 함)
2. 보안 구성에 따라 URL 유효성 검사
3. 차단 시: 오류 발생 및 차단된 액세스 기록
4. 허용 시: 가져오기 진행 및 성공적인 유효성 검사 기록

### websearch 도구

`websearch` 도구는 MCP 엔드포인트 URL을 유효성 검사합니다:

1. MCP 엔드포인트 URL 생성: `https://mcp.exa.ai/mcp`
2. 보안 구성에 따라 유효성 검사
3. 차단 시: 오류 발생 및 차단된 액세스 기록
4. 허용 시: 검색 실행 및 성공적인 유효성 검사 기록

### 도구 유효성 검사 흐름

```
Tool Request → Config Retrieved → Security Validated → Allowed? → Fetch / Error
                                           ↓ Yes
                                      Proceed
                                           ↓ No
                                      Log & Block
```

## 참고 사항

- 보안 유효성 검사는 도구 실행 및 프로바이더 로드 **이전**에 발생합니다
- 감사 로깅은 결과와 무관하게 활성화된 경우 **항상** 적용됩니다
- `strict` 모드에서는 `external_domains`, `allow_internal_dns_suffixes`에 명시적으로 없거나 `allowed_ip_ranges`와 일치하지 않는 한 **아무것도** 허용되지 않습니다
- `allow_local` 및 `allow_private_ip`의 기본값은 `true`입니다
- `allow_external_ips`의 기본값은 `false`입니다
